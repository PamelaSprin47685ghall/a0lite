# FD 增长根因：v18（PID 2123135）与 v19（PID 2158804）

- 触发：v18 soak 有效窗口 31.2 分钟 FD 86→147（+61），超 ≤30 阈值。
- 方法：v18 已采曲线 + v19 定向复现（health/chat 请求逐次采样），未跑大 OCR/嵌入。

## §1 FD 曲线形态

- v18（soak-v18.csv）：83→147，31 分钟 +64，**阶梯式而非线性**。相邻差分 −3…+11，聊天后的采样跳 +6~+11，其余多 +0~+3；本质是「请求堆积 + 延迟回收」叠加缓慢基线抬升。
- v19 空闲对照（无任何请求）：07:36:19 fd=62、07:36:59 fd=62、07:38:18 fd=62，**2 分钟完全稳定**；另一次 07:29:22 的 15 请求后在 10 s 内 171→42。
- 结论：v18 的 +61 不是单调永久泄漏，而是**回收滞后造成的高水位**；v19 空闲可回到 62。

## §2 FD 类型分布（v19 停止加压后，fd=62）

| 类型 | 数量 | 说明 |
|---|---:|---|
| socket | 31 | 18080、11434、5080、监听 |
| anon_inode:[eventpoll] | 14 | asyncio loop 的 epoll |
| pipe | 8 | 4 对，恒定，无子进程泄漏 |
| inotify / file / 其他 | 11 | watchdog 4、日志 5、pidfd+deleted 2 |

- 加压时 socket 与 eventpoll **同比例 +2/+1**，即每个请求新增 1 组「socketpair + epoll」。

## §3 ESTAB / CLOSE_WAIT 与对端

| 项 | v18 空闲 | v19 空闲 | 判定 |
|---|---:|---:|---|
| 到 127.0.0.1:18080（zproxy 出站） | 4–6 | 3–6 | 不随 FD 增长 |
| 到 127.0.0.1:11434（Ollama） | 3–6 | 3–4 | 不随 FD 增长 |
| sport 5080（浏览器） | 1–2 | 1–2 | 稳定 |
| CLOSE_WAIT | 0 | 0 | 无未关闭 |

- ESTAB 稳定 + FD 增长 → 排除「连接池不复用/未关闭」与「CLOSE_WAIT 堆积」。

## §4 定向复现（每次请求的净增量）

| 负载 | 结果 |
|---|---|
| 20× GET /api/health（连续） | 每次 **+3 fd**（socket +2、eventpoll +1）；20 次 63→123 |
| 15× / 12× GET /api/health | 15 次峰值 171 → idle 10 s 回落 **42**；12 次 idle 5 s 后 104→67 |
| 8× POST /api/message（短聊天） | 每轮 +3~+7，聊天结束回落；无永久增长 |
| 4 分钟完全空闲 | 62 → 62，零增长 |

- 每次 HTTP 请求固定新增 3 个 fd，属**每请求事件循环/self-pipe**；持续请求时回收滞后，形成 100–170 的高水位，停止后回到 62。
- 没有「某类业务请求每次泄漏 N 个且不回收」的证据；OCR/TTS/STT/嵌入未单独加压（避免污染）。

## §5 根因判断

- 排除 httpx/aiohttp 连接池（ESTAB 平）、子进程管道（pipe 恒 8）、CLOSE_WAIT；指向 **asyncio 事件循环的每请求创建/延迟关闭**：`helpers/api.py::_dispatch` 每请求实例化 handler，配合 `a2wsgi`/uvicorn 的 loop 管理，产生 1 组 socketpair+epoll；引用释放依赖 GC，故在请求密集时堆积、空闲后回收。
- v18 的缓慢基线抬升（~1 fd/min）另有一份可能来自 scheduler/plugin 周期任务，但 v19 空闲 2 分钟零增长，未复现为永久泄漏。

## §6 修复方向

- 核心修复不在 `a0flatpak` 层：应查 `helpers/api.py` 的 dispatch 与 `a2wsgi` 配置，避免每请求新建 loop/self-pipe；复用 uvicorn 的单一 loop。
- a0flatpak 可加低成本护栏：FD > 400 时把 fd 类型 top5 写入日志，便于长跑取证。
- 不建议在该层做 fd 强制回收（会破坏 asyncio 语义）。

## §7 严重度

- **不阻塞交付**：v19 空闲稳定 62，峰值 171 < 1024；无 CLOSE_WAIT、无 ESTAB 堆积、无 OOM、health 200、聊天 200。
- 记为 **K06（低–中）**：请求密集时 FD 高水位 + 回收滞后；长跑（>2 h 持续请求）需复测是否收敛。
